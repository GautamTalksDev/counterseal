How it works

Three beats. One tap.

The irreversible map covers 10 APIs: GitHub, Cloudflare, Railway, Stripe, Supabase, Vercel, Neon, Fly.io, Resend and Shopify. Management APIs only; SQL sent straight over a database connection string never passes through Counterseal.

  1. 1

    Vault the key

    Paste it once. It is encrypted in the vault. Your agent gets a scoped Counterseal token instead.

  2. 2

    The call is held

    Anything it can't take back, like a delete, refund or deploy, waits. Reads and other writes go straight through.

  3. 3

    You seal it

    Your phone asks. Approve with a passkey, or deny. Every decision on a write becomes a receipt anyone can verify.

New

Budget seal. A cap on model spend.

Set a daily or monthly cap per agent, per key or for the whole account. At the cap the next call gets 402 budget_exhausted and is never sent. Provider alerts tell you later; this stops the next call.

  • "Ask me" mode: past 80%, your passkey decides if it goes on.
  • Runaway detector trips an agent that fans out too fast.
  • Raising a cap takes a passkey, never a command line.

Caps only model calls that go through Counterseal, on the two model APIs listed in the docs. It does not cap your cloud bill, keys used directly, or other tools. One call can pass the cap by its own cost; nothing goes after it.

What it does not do.

You trust us with the key

Each key is encrypted on its own (AES-256-GCM) and no API ever returns it, but the hosted service decrypts it to forward a call. Start with a test key.

Only calls that pass through

A key in a .env file, a direct database connection or another tool is never seen.

A seatbelt, not a sandbox

The local coding agent guard matches a map of commands. For a hard stop, use a token instead of the real key.

The map is a reviewed list

A call it does not know to be irreversible goes through. Add hold rules to a token's policy for anything else you care about.
